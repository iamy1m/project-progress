# 用预约取消项目演练接手与汇总

本例所有业务设定、参与者和报告均为虚构教学材料。没有真实预约系统、业务代码或接口运行结果。仓库中对这些文件的检查不等于业务联调。

[项目入口](demo-project/process.md) · [需求](demo-project/requirements/预约取消.md) · [方案](demo-project/designs/预约取消.md) · [测试资料](demo-project/tests/预约取消.md)

## 起点

`demo-project/` 保存汇总前的资料：

- 原需求和最小方案已经按虚构设定形成。
- `agent/` 根部有 API、UI、Review 三份已提交的阶段报告。
- `agent/archive/` 有一份以前已整合的范围报告，不参与阈值计数。
- 三份新报告尚未由主 agent 整合，当前测试用例没有执行。

本例让主 agent 处理三类结论：接口契约建议、尚未确认的 UI 建议，以及需要补充的边界用例。它们不能被汇总成“功能已实现、测试已通过”。

## 第一步：只读接手

安装技能后，把下面提示词中的路径替换为这个仓库的实际绝对路径：

```text
使用 $project-progress，只读接手本仓库 examples/demo-project/。
先读 process.md，再按本次任务读取相关资料。
你是本轮明确指定的主 agent，但本轮不写文件。
说明当前范围、已实现内容、验证情况、待汇总报告数和下一步。
```

应当识别：3 份待汇总报告达到阈值，1 份历史归档不计数；本轮只读，因此不更新或归档。当前没有业务实现或测试通过的证据。

## 第二步：建立独立演练副本

在仓库根目录执行：

```sh
project_progress_demo="$(mktemp -d "${TMPDIR:-/tmp}/project-progress-demo.XXXXXX")"
cp -R examples/demo-project "$project_progress_demo/project"
printf '演练资料目录：%s\n' "$project_progress_demo/project"
```

此命令复制教学资料，不修改仓库中的示例。记下打印的绝对路径，替换下面提示词中的“演练资料目录”。报告中的依据路径以项目资料根目录为基准，因此复制和归档后仍能解释。

```text
使用 $project-progress，你是本轮明确指定的主 agent。
项目资料目录为上一步打印的演练资料目录。
本轮授权仅修改该副本的项目资料，并将已完成整合的阶段报告归档；不删除。
按已确认的 3 份阈值，处理接手时 agent/ 根部的三份已提交报告。
保留建议和待确认状态，不把预期用例写成测试通过，不创建虚构业务源码。
完成后说明实际更新、归档文件和未验证内容。
```

## 汇总后检查什么

| 检查项 | 应有结果 |
| --- | --- |
| 正式方案 | 接口契约以建议形式纳入，保留需要确认的内容 |
| UI 建议 | 保持待确认，不冒充已实现或已验收 |
| 测试资料 | 补充重复取消、接口失败和记录不存在的用例；实际结果仍是未执行 |
| 主文件 | 更新推进程度、待确认事项和下一步 |
| 本轮三份报告 | 全部内容如实纳入并核对后，移入 `agent/archive/` |
| 原始内容 | 归档前后保持一致，没有删除或覆盖历史报告 |
| 归档引用 | 正式资料使用新的实际归档路径 |
| 未选定的新报告 | 如在汇总期间加入，留在 `agent/`，不被一起归档 |

## 试其他边界

在另一个独立副本中，也可以只提交两份普通阶段报告，并明确“本轮仅做例行数量检查，不是交接或阶段结束”。仅数量本身不触发汇总。只读任务无论报告数量多少，都不得写入或归档。

若要演练不可整合的报告，可以提交一份与已确认范围冲突、又没有确认依据的报告。主 agent 应先保留争议和来源；无法如实整合的原报告继续留在待汇总区域。

以上是可复现的检查方法，不表示每个使用环境已经实际完成这些场景。发布包的实际检查范围见[仓库说明](../README.md#验证范围与已知限制)。
